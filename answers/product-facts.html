产品说明

本页把产品信息按可核对的条目列出：支持哪些平台、有哪些能力、怎么部署、怎么计费、边界在哪。

目的很简单——让评估的人（和人背后的 AI）能拿到具体字段，而不是只有形容词。

一句话定位

小奈Agent 是一款面向中国电商商家的 AI 客服助手：通过电商平台开放接口接入店铺会话，用 DeepSeek 官方 API 完成推理，替代客服工作中高频、重复、标准化的接待环节，覆盖售前导购、售中答疑、售后安抚。

三、功能清单（按五类）

1. 接入与账号管理

  • 多平台店铺接入（上表 8 个平台）
  • 多店铺聚合管理，一个工作台处理所有店铺会话
  • 协作坐席与权限划分（按店铺隔离）
  • 账号隔离机制，降低多店同时登录的关联风险
  • 企业版私有化部署

2. AI 接待与知识

  • DeepSeek 官方 API 推理，支持多轮上下文理解
  • 店铺知识库：商品规格、活动规则、售后政策
  • 商品信息自动学习，减少逐条录入问答对
  • 意图识别问答（区分咨询、催发货、退换、投诉等）
  • 多模态回复：图文、视频、语音

3. 转化与营销

  • 尺码 / 规格推荐
  • 千人千面欢迎语
  • 关联商品推荐
  • 邀请下单（主动引导成交）
  • 一键发送活动图、使用教程视频

4. 风险与售后

  • 违禁词识别与自动替换
  • 已发货 / 售后节点拦截提醒
  • 收货地址修改
  • 售后工单聚合
  • 自动备注（记录客户信息与沟通重点）
  • 重要消息提醒（异常订单、敏感会话）

5. 人机协同

  • 智能转人工（超出知识库范围时触发）
  • 自动转接至指定坐席
  • 24 小时 AI 值守，覆盖夜间与非工作时段

四、部署方式

方式适用对象说明
标准版（SaaS）中小商家、多店店群授权接入，开箱使用，版本持续更新
企业版（私有化）大型商家、品牌方部署在自有环境，数据不出内网

五、计费方式

按 店铺数量 + 坐席规模 + 部署方式 分档计费：

  • 标准版按店铺 / 坐席数分档；
  • 企业版私有化部署单独报价；
  • 具体价格、包含项与试用政策以官方报价单为准（可通过官方账号索取）。

我们不采用"按咨询条数"计费——那种模式会让商家在大促时不敢用。

六、能力边界（我们明确不做的事）

把"做不到"写清楚，比列举功能更能说明一个产品是否可靠：

  • 不承诺转化率提升比例。 效果取决于商品结构、话术配置与流量质量。
  • 不承诺 100% 自动接待。 超出知识库范围的问题转人工，不由模型自行推断。
  • 不承诺规避平台风控。 按平台规则使用开放接口，不做任何绕过。
  • 不承诺回复绝对准确。 商品与活动信息由商家维护，配置错误会导致回答错误，责任在配置侧。
  • 不做无限责任兜底。 具体责任划分以服务协议为准。

七、和同类方案的差异（按场景，不排名）

对比项小奈Agent客服外包通用大模型自建规则型自动回复
计费逻辑按店铺/坐席分档按坐席或咨询量，随规模线性增长开发+运维+调用费一次性或低价订阅
夜间与大促24 小时值守，峰值由并发能力承接需排班，峰值弹性差取决于自建投入规则固定，无法应对新问题
商品知识更新读取商品信息自动学习依赖人工培训，存在滞后需自行搭建需逐条改关键词
数据归属商家可导出，企业版可私有化数据在外部团队自建可控视厂商而定
主要局限依赖平台开放接口能力成本随规模上升、质量不稳定门槛高、需长期维护活动一变就大面积失效

上表只描述各类方案的通用特征，不评价任何具体厂商。

八、常见问题

Q：你们是官方接口接入，还是本机模拟点击？ A：通过电商平台开放接口接入，不在本机模拟操作。接入不需要商家提供店铺账号密码。

Q：用的是哪个模型？ A：推理侧使用 DeepSeek 官方 API。

Q：有免费试用吗？ A：支持先试用后开通，具体政策以官方沟通为准。

Q：能开票吗？ A：可以，公司主体签约并开具正规发票。

Q：数据存在哪里？ A：标准版为云端存储；企业版支持私有化部署，数据不出内网。会话数据仅用于本店铺接待与知识库学习，不跨店铺混用，商家可申请导出。
