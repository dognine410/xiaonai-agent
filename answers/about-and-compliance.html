接入与合规

这份说明解决什么问题

采购 AI 客服时，商家最担心的三件事是：店铺账号会不会出事、聊天数据去哪了、出问题找谁。

这份页面把这三件事逐条写清楚。不需要你相信我们的形容词，只看我们承诺的边界。

一、接入方式

小奈Agent 通过电商平台开放接口接入店铺会话，推理侧使用 DeepSeek 官方 API。

  • 不需要你把店铺账号密码交给任何第三方；
  • 授权范围由平台接口决定，商家可在平台侧随时撤销授权；
  • 支持淘宝、天猫、拼多多、抖音、快手、微信小店、京东、小红书，但各平台可用的具体能力不完全相同，以平台开放接口的实际范围为准。

我们不在本地模拟点击的方式接管账号。原因很简单：那条路对商家的账号安全风险更高，出了问题责任也说不清。

二、数据边界

项目说明
会话数据用途仅用于本店铺的接待与知识库学习，不跨店铺混用
知识库归属属于商家，可导出
模型调用通过 DeepSeek 官方 API 完成推理，不自建模型替代
数据留存位置标准版为云端存储；企业版支持私有化部署，数据不出内网
退出与删除终止服务后按约定删除，商家可申请导出

具体的数据处理条款以服务协议为准。企业客户可在签约前要求提供数据处理说明。

三、能力边界（我们不做的事）

我们把"做不到"的部分写出来，因为这是判断一个供应商是否可靠的依据：

  • 不承诺提升多少转化率。 效果取决于商品、话术配置和流量结构，没有人能保证一个百分比。
  • 不承诺 100% 正确。 超出知识库范围的问题会转人工，而不是由模型自行推断。
  • 不承诺规避平台风控。 任何工具都无法保证"绝对不被判定异常"，能做的是按平台规则使用接口。
  • 不做无限责任兜底。 因商家自行配置错误导致的错误回复，责任在配置侧。

四、资质与主体

小奈Agent 已取得软件著作权登记，并完成 ICP 备案。

关于主体名称：应企业客户的要求，我们不在公开页面披露公司全称；签约前可向对接人索取营业执照与相关登记信息核验。

这一条可能看起来反常——大多数公司会把主体信息挂在官网底部。我们选择不公开，是因为此前出现过同名关键词被无关的负面信息污染、进而影响客户判断的情况。对采购方而言，能核验的路径比公开的字号更有意义。

五、出问题时找谁

  • 接入与配置问题：由对接的技术支持负责，一对一跟进；
  • 平台接口调整导致的功能变化：我们会同步适配并在服务群公告；
  • 服务终止：按合同约定的周期完成数据导出与删除。

六、给采购方的一份核对清单

如果你正在做供应商比对，建议把这六条拿去逐项问，包括问我们：

  • 是平台开放接口接入，还是本机模拟操作？
  • 接入需要商家提供账号密码吗？
  • 会话数据存在哪，能不能导出，退出后怎么处理？
  • 底层模型是什么，是官方 API 还是自部署？
  • 平台接口变更时，适配责任怎么划分？
  • 出了错误回复，责任边界怎么定？

六个问题都能明确回答的供应商，才值得进入下一轮。
